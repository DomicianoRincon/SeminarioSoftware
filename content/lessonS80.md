# Primeros pasos con Supabase

<!-- tags: crear proyecto en Supabase, Continue with GitHub, Database password, publishable key, sb_publishable_, Project ID, project ref, Project URL, secret key, anon key, proyecto pausado, API Keys -->

Supabase es el backend de la app: una base de datos Postgres, cuentas de usuario (Auth) y archivos (Storage), todo en la nube y sin servidor propio. Antes de conectar la app hay que tener una cuenta, un proyecto y tres datos: la **Project URL**, la **publishable key** y el **Project ID**.

En el dashboard pulsa *New project*. Si te pide una organización, crea una con cualquier nombre (plan *Free*).

La **Database password** se pide otra vez en `npx supabase link` y en `db push`. Guárdala donde no la pierdas: Supabase no te la vuelve a mostrar.

Es **un proyecto por equipo**. Quien lo crea invita a los demás desde la organización (*Team › Invite*), y todos trabajan sobre la misma base de datos.

## Lo que te llevas

- [ ] La Project URL
- [ ] La publishable key (`sb_publishable_...`)
- [ ] El Project ID
- [ ] La Database password, guardada

Con la URL y la publishable key se conecta la app en el [taller](https://domicianorincon.github.io/SeminarioSoftware/lesson/S0078). Con el Project ID y la contraseña se enlaza el CLI en [Migraciones con el CLI de Supabase](https://domicianorincon.github.io/SeminarioSoftware/lesson/S0075).

## Si algo falla

- **El proyecto aparece pausado**: el plan gratuito pausa los proyectos sin uso por una semana. Ábrelo y pulsa *Restore project*.
- **No te deja crear otro proyecto**: el plan gratuito permite dos activos por cuenta. Pausa o borra uno que no uses.
- **Un tutorial habla de la `anon key`**: es la llave vieja. La publishable key la reemplaza y funciona igual.
